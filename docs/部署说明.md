# 信渡 Linux 部署说明

推荐使用 Linux、独立低权限用户和 systemd。生产公网服务建议放在 Caddy 或 Nginx 后面启用 HTTPS；若暂时直接暴露端口，必须明确配置防火墙。

## 部署前需要准备

- 服务器 IP 或域名及 SSH 登录权限。
- Python 3.10+ 与 SQLite 3.35+。
- 对外访问地址，例如 `https://pickup.example.com`。
- 后台管理员密码。
- 按 `examples/待导入邮箱/示例账号组.txt` 准备的真实邮箱文件夹。
- 域名与 HTTPS、开放端口和停机窗口等生产决策。

## 安装文件

以下示例使用 `/opt/pickup-server` 和系统用户 `pickup`：

```bash
sudo useradd --system --home /opt/pickup-server --shell /usr/sbin/nologin pickup || true
sudo install -d -o pickup -g pickup -m 750 /opt/pickup-server
sudo install -d -o pickup -g pickup -m 700 /opt/pickup-server/data
sudo install -o pickup -g pickup -m 750 pickup_server/app.py /opt/pickup-server/app.py
sudo install -o pickup -g pickup -m 644 pickup_server/favicon.ico /opt/pickup-server/favicon.ico
```

检查目标环境：

```bash
python3 --version
python3 -c 'import sqlite3; print(sqlite3.sqlite_version)'
python3 -m py_compile /opt/pickup-server/app.py
```

## 初始化与导入

为了避免后台密码出现在 shell 历史中，可通过标准输入初始化：

```bash
read -rsp "后台密码: " PICKUP_ADMIN_PASSWORD; echo
printf '%s' "$PICKUP_ADMIN_PASSWORD" | sudo -u pickup \
  PICKUP_SERVER_HOME=/opt/pickup-server \
  python3 /opt/pickup-server/app.py init \
  --admin-password-stdin \
  --base-url "https://pickup.example.com"
unset PICKUP_ADMIN_PASSWORD
```

导入邮箱并生成 URL：

```bash
sudo install -d -o pickup -g pickup -m 700 /opt/pickup-server/output
sudo -u pickup PICKUP_SERVER_HOME=/opt/pickup-server \
  python3 /opt/pickup-server/app.py import \
  --source "/安全位置/待导入邮箱" \
  --base-url "https://pickup.example.com" \
  --output "/opt/pickup-server/output/取件URL.txt"

sudo -u pickup PICKUP_SERVER_HOME=/opt/pickup-server \
  python3 /opt/pickup-server/app.py audit-urls \
  --input "/opt/pickup-server/output/取件URL.txt"
```

## systemd

创建 `/etc/systemd/system/pickup-server.service`：

```ini
[Unit]
Description=Pickup URL Server
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=pickup
Group=pickup
WorkingDirectory=/opt/pickup-server
Environment=PICKUP_SERVER_HOME=/opt/pickup-server
# 可选：仅在明确接受把访问者 IP 发送给第三方 HTTPS 归属地服务时启用
# Environment=PICKUP_ENABLE_IP_GEO=1
ExecStart=/usr/bin/python3 /opt/pickup-server/app.py serve --host 127.0.0.1 --port 8080
Restart=always
RestartSec=3
NoNewPrivileges=yes
PrivateTmp=yes
PrivateDevices=yes
ProtectHome=yes
ProtectSystem=full
ReadWritePaths=/opt/pickup-server
RestrictAddressFamilies=AF_INET AF_INET6 AF_UNIX

[Install]
WantedBy=multi-user.target
```

若不使用反向代理、需要直接访问 `8080`，把 `--host 127.0.0.1` 改为 `--host 0.0.0.0` 并只开放必要来源。不要把纯 HTTP 管理后台直接暴露到公网。

启动并检查：

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now pickup-server
sudo systemctl status pickup-server --no-pager
curl --fail --max-time 3 http://127.0.0.1:8080/health
curl --max-time 10 http://127.0.0.1:8080/ready
```

查看日志和重启：

```bash
sudo journalctl -u pickup-server -n 200 --no-pager
sudo journalctl -u pickup-server -f
sudo systemctl restart pickup-server
```

## 更新与回滚

更新前必须停止服务，并把 SQLite 与 `.env` 成对备份：

```bash
stamp=$(date -u +%Y%m%d%H%M%S)
sudo systemctl stop pickup-server
sudo install -d -o root -g root -m 700 "/opt/pickup-server/backup-$stamp"
sudo cp -a /opt/pickup-server/app.py "/opt/pickup-server/backup-$stamp/"
sudo cp -a /opt/pickup-server/favicon.ico "/opt/pickup-server/backup-$stamp/"
sudo cp -a /opt/pickup-server/.env "/opt/pickup-server/backup-$stamp/"
sudo cp -a /opt/pickup-server/data "/opt/pickup-server/backup-$stamp/"
sudo install -o pickup -g pickup -m 750 pickup_server/app.py /opt/pickup-server/app.py
sudo install -o pickup -g pickup -m 644 pickup_server/favicon.ico /opt/pickup-server/favicon.ico
sudo -u pickup python3 -m py_compile /opt/pickup-server/app.py
sudo systemctl start pickup-server
curl --fail --max-time 3 http://127.0.0.1:8080/health
```

需要回滚时停止服务，把同一个 `backup-时间戳` 目录中的 `app.py`、`favicon.ico`、`.env` 和 `data` 一起恢复，再启动服务。不要只恢复数据库主文件或只更换 `.env`。

## 验收标准

- `/health` 返回 200、`ok=true`，且 `version` 与部署版本一致。
- 至少一个可用账号组成功扫描后，`/ready` 返回 200。
- `/admin` 可以登录，未登录访问 `/admin/api/data` 返回 401。
- 随机取件页面与对应 API 返回 200。
- 给测试邮箱发送带唯一标记的 canary 邮件，能在预期时间内出现且邮箱与 URL 映射正确。
- `fetch.pending=true` 时调用方会按建议等待重试。
- IMAP 异常组为 0，或每个异常都有明确原因。
