# 信渡技术说明

## 项目定位

服务主体为 `pickup_server/app.py`，使用 Python 标准库实现 HTTP 服务、SQLite 数据存储、IMAP 拉取、后台页面和命令行工具。当前版本可通过 `/health` 返回的 `version` 字段核对。

## 默认运行路径

程序默认以 `pickup_server` 目录作为应用目录：

- `.env`：`pickup_server/.env`
- SQLite：`pickup_server/data/pickup.db`

可以用环境变量覆盖：

| 变量 | 用途 |
|---|---|
| `PICKUP_SERVER_HOME` | 应用目录 |
| `PICKUP_DATA_DIR` | 数据目录 |
| `PICKUP_DB` | SQLite 文件 |
| `PICKUP_ENV` | `.env` 文件 |
| `PICKUP_PORT` | `serve` 默认端口 |
| `PICKUP_ENABLE_IP_GEO` | 设为 `1` 时启用外部 IP 归属地查询；默认关闭 |

## 数据模型

- `settings`：后台密码 hash、对外 base URL、轮询间隔等配置。
- `groups`：IMAP 主邮箱账号组、应用密码、扫描状态、连续 UID 游标和 `UIDVALIDITY`。
- `mailboxes`：取件邮箱、随机 token、token hash 和启用状态。
- `messages`：邮件缓存，按账号组和 UID 去重。
- `access_events`：页面/API 访问记录及状态码。
- `ip_geo_cache`：IP 归属地缓存。

## 取件流程

1. 用户打开 `/q/<token>`，页面请求 `/api/q/<token>/messages`。
2. 服务端通过 token hash 定位单个邮箱，只在所属 IMAP 账号组内查询。
3. 同组并发刷新会合并；API 默认有界等待 5 秒。
4. 实时路径检查 INBOX 最新窗口，并按需受限搜索 Junk/Spam 候选文件夹。
5. 后台轮询持续补齐邮件，完整扫描和实时扫描使用独立状态。
6. 最终只返回收件人精确匹配目标邮箱的邮件。

## 公共 API 契约

```text
GET /api/q/<token>/messages?wait=5&limit=30
```

- `messages`：最多返回 `limit` 条，允许范围 1–100；每条带稳定 `id`。
- `fetch.state`：`pending`、`ready`、`cached`、`degraded` 或 `error`。
- `fetch.pending=true`：刷新尚未完成，调用方必须稍后重试。
- `fetch.fresh=true`：本次请求等到一轮成功刷新。
- `last_success_at`：最近一次成功连接和扫描时间。
- `last_attempt_at`：最近一次尝试时间，不代表成功。
- IMAP 暂时异常时，已有缓存仍可返回。

`wait=0` 适合只读缓存的高并发探测；默认 `wait=5` 兼顾及时性和容量。

## 健康检查

- `/health`：服务与数据库可访问时返回 200，同时报告版本、降级状态、异常组和过期组。
- `/ready`：所有启用组均不可用时返回 503，适合部署验收和流量切换。

不能只凭进程存在或 systemd 显示 `active` 判断服务可用，应同时核对 `/health`、`/ready` 和真实取件链路。

## 安全设计

- 公共 URL 使用 `pk_` 前缀和密码学安全随机 token。
- 数据库保留明文 token 供后台导出，同时用 `.env` 中的 `PICKUP_TOKEN_PEPPER` 计算查询 hash。
- 后台 session 使用 `PICKUP_SESSION_SECRET` 签名。
- 后台密码使用 PBKDF2-HMAC-SHA256 存储。
- `serve` 默认只监听 `127.0.0.1`，需局域网开放时由部署者显式选择。
- 对外地址为 HTTPS 时，后台 Cookie 自动附加 `Secure`，并始终使用 `HttpOnly` 与 `SameSite=Lax`。
- IP 归属地查询默认关闭；启用后只允许请求 `https://ipwho.is` 与 `https://ipapi.co`。
- HTTP 日志会将 `pk_...` 脱敏为 `[token]`。
- 后台 `/admin/api/*` 接口要求登录。
- 导入时拒绝把同一个取件邮箱静默改绑到不同账号组。

## CLI

```text
init          初始化 .env、数据库、后台密码和 base URL
import        导入邮箱账号组，可同时导出 URL
export        导出当前有效 URL
check-imap    主动刷新并报告全部 IMAP 账号组
audit-urls    脱敏检查 URL 文件格式、重复和端点
convert-urls  在 ---- 与 Tab 分隔格式间无损转换
serve         启动 HTTP 服务
```

运行 `python pickup_server/app.py <命令> --help` 可查看参数。

## 修改约束

- 取件查询必须保持 `group_id` 隔离，不能只按邮箱字符串全库搜索。
- 日志必须继续脱敏 `pk_...`。
- 后台接口必须保持登录校验。
- 修改数据库结构时必须兼容旧数据并保留现有 token。
- 修改实时拉取逻辑时应同时验证 INBOX、垃圾箱、并发等待、旧缓存和 IMAP 失败路径。
- 修改后至少运行 `python -m unittest discover -s tests -v`，并在目标环境验证 `/health`、`/ready`、后台登录和真实 canary 邮件。
